## Що зроблено та як працює логіка
* **Ручний 2-pass Union-Find CCL (`connected_components_label`):** замість повільного попіксельного циклу на кадрі 2 Мп у першому проході по кожному рядку виділяються горизонтальні прогони переднього плану `[start, end)`, які зв'язуються із сусіднім рядком за точною умовою 8-зв'язності (`s1 <= e2` та `s2 <= e1`) за допомогою Disjoint Set Union (Union-Find) із компресією шляхів; у другому проході корені перенумеровуються у послідовні ID `1..K`.
* **Ручний розрахунок геометрії (`compute_component_geometry`):**
  * обмежувальний прямокутник `bbox` і вирізання локальної підмаски для економії пам'яті й часу;
  * ручний обхід зовнішнього контуру **Moore-Neighbor tracing** (ортогональний крок `1.0`, діагональний `sqrt(2)`) із зовнішньою поправкою `+4.0` для одиничних пікселів (забезпечує точний периметр `2(a+b)` для будь-якого прямокутника й окружність `pi/4 = 0.7854 < 0.82` для квадрата проти `0.8413 >= 0.82` для круга `r=15`);
  * ручний **PCA Oriented Bounding Box (OBB)**: замкнена форма $2\times 2$ коваріаційної матриці координат пікселів та кут головної осі $\theta = \frac{1}{2}\operatorname{atan2}(2\sigma_{xy}, \sigma_{xx} - \sigma_{yy})$, проєкція координат і обчислення інваріантного до повороту `aspect_ratio`.
* **Класифікація (`classify_shapes`):** автоматично розрізняє бінарні маски (`{0, 1}` / `{0, 255}`) та готові інстанс-маски (`1..K` від Watershed П3), відсіває сміття за `min_area_ratio * stud_size_px^2`, зіставляє ознаки з таблицею класів із `configs/default.json` та враховує опційні `stud_counts` / `texture_features` із `pipeline_metadata`.
