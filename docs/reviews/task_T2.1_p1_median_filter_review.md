## Що зроблено та як працює логіка
* Реалізовано `_pad_reflect_safe`: симетрично доповнює кожен 2D-канал методом `reflect` на величину радіуса `pad = kernel_size // 2`, автоматично перемикаючись на `edge` уздовж осей, коротших або рівних `pad` (виключає помилки NumPy на мінімальних кадрах на кшталт `1×N` чи `2×2` при `kernel_size=5`).
* Реалізовано `_median_filter_2d` та публічну `median_filter_manual`:
  * перевіряє коректність параметрів (непарне ціле `kernel_size >= 1`, не `bool`, непорожній 2D/3D масив);
  * обробляє канали смугами по `64` рядки за допомогою `np.lib.stride_tricks.sliding_window_view` і часткового сортування `np.partition(..., mid, axis=-1)[..., mid]`, що знаходить точну медіану за $O(k^2)$ на піксель і тримає пікове споживання RAM на рівні ~3 МБ навіть для кадрів `1600×1200×3`.

## Потенційні вузькі місця та рекомендації
1. На кадрі `1600×1064×3` з вікном `5×5` фільтр виконується ~`1.72 с`; при збільшенні вікна до `7×7` або `9×9` час зростає пропорційно $k^2$, тому в конфізі доцільно залишати `kernel_size = 5` або `3`.
2. Для імпульсного шуму великої щільності (`p > 0.25`) вікно `3×3` може пропускати кластери викидів, натомість `5×5` усуває їх надійніше ціною незначного згладжування найдрібніших деталей.
3. Покрити тестом у `T2.5` матрицю `3×3` з одиничним імпульсним викидом `255` і перевірку помилки для парного `kernel_size`.
