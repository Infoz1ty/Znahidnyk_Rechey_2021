# AGENTS.md — Правила розробки STEM-проєкту «Знахідник речей» (LEGO Classical CV)

Цей файл визначає обов'язкові технічні, архітектурні та академічні правила для AI-агентів і розробників у репозиторії `Znahidnyk_Rechey_2021`.

---

## 1. Контекст і політика Zero-ML & Manual-CV

Проєкт реалізує класичну систему комп'ютерної графіки та цифрової обробки зображень для виявлення, класифікації (форма, тип поверхні, колір) та пошуку деталей LEGO на одношарових розсипах (зйомка зверху під $90^\circ$, гібридна вибірка 110–120 PNG-зображень).

* **СУВОРО ЗАБОРОНЕНО AI/ML:** жодних нейромереж, Deep Learning чи алгоритмів машинного навчання (`torch`, `tensorflow`, `keras`, `ultralytics`, `yolo`, `mediapipe`, `scikit-learn`, предобучених моделей).
* **СУВОРО ЗАБОРОНЕНО вбудовані CV-алгоритми (Методичка, стор. 12–13):** **усі** стадії пайплайнів, класифікатори й метрики реалізуються **вручну**. Заборонено викликати `cv2.*` (`medianBlur`, `Canny`, `Sobel`, `bilateralFilter`, `watershed`, `HoughCircles`, `minAreaRect`, `erode`, `morphologyEx`, `threshold`, `cvtColor`, `distanceTransform`, `connectedComponents`, `findContours`), `scipy.ndimage`, `scikit-image` (`skimage.*`) або фільтри `PIL.ImageFilter`.
* **Дозволена межа бібліотек:**
  * **Алгоритми обробки, класифікатори та метрики:** стандартна бібліотека Python (`math`, `heapq`, `collections`) + базові матричні операції `numpy` (масиви, зрізи, індексація, поелементна арифметика; для 2D FFT у П4 — ручний алгоритм Кулі–Тьюкі Radix-2).
  * **Введення/виведення та візуалізація:** виключно `Pillow` (`PIL.Image`, `PIL.ImageDraw`, `PIL.ImageFont`) у `image_io.py` та `visualizer.py`.
  * **Аналітика звіту:** `matplotlib` лише у `scripts/compare_pipelines.py`.
  * **Офлайн-підготовка RAW:** `rawpy` лише у `scripts/convert_raw.py`.
  * **Якість і тести:** `pytest`, `pylint`.
* **Заборона дублювання лабораторних робіт №5–6:** перед додаванням або заміною будь-якого методу перевіряйте, що він не повторює методи, реалізовані в лабах №5–6 (звіряйте з `docs/tz.md`).

## 2. Архітектурний контракт (Двокроковий конвеєр + 3 стадії)

Усі 4 пайплайни (`p1`–`p4`) наслідують `BasePipeline` (`src/lego_cv/core/base_pipeline.py`) і працюють за єдиною двокроковою схемою, описаною в `docs/architecture.md`.

### Контракт `BasePipeline` (вхід і вихід пайплайну)
1. Кожен пайплайн приймає вхідне зображення **`RGB` `uint8` форми `(H, W, 3)`** (не `BGR`!), завантажене через `src/lego_cv/core/image_io.py`, і словник `config`.
2. Кожен пайплайн зобов'язаний реалізувати 3 послідовні методи з **3 різних категорій методички**:
   * `stage1_preprocess(image_rgb, config) -> (stage1_img, state)`
   * `stage2_segment(stage1_output, state, config) -> (stage2_img, state)`
   * `stage3_refine(stage2_output, state, config) -> (final_mask, stage3_visual, metadata)`
3. Базовий метод `BasePipeline.run()` автоматично вимірює час кожної стадії й повертає `PipelineResult`:
   * `denoised` — вихід Стадії 1 (використовується для обчислення `PSNR`, `MSE`, `SSIM`);
   * `mask` — бінарна (`0/1`) або інстанс-маска (`0, 1..K`, обов'язково для `p3` Watershed) типу `int32`;
   * `stages` — список із 3 об'єктів `StageOutput` для автоматичного збереження `stage_1..3` PNG (обов'язкова вимога методички);
   * `metadata` — додаткові ознаки (наприклад, кількість шпильок `stud_counts` та `texture_features` із `p4`).

### Крок 1: Геометрія форми (`src/lego_cv/core/shape_classifier.py`)
Спільний Модуль А приймає `mask` і `metadata` та визначає клас форми й тип поверхні кожної деталі **ручними алгоритмами**:
* ручне маркування зв'язних компонентів (2-pass Union-Find CCL, якщо маска бінарна);
* фільтрація дрібного сміття ($S < 0.5 \cdot S_{1\times 1}$);
* нормована площа $N = S / S_{1\times 1}$;
* співвідношення сторін орієнтованого прямокутника $AR = \max(w, h) / \min(w, h)$ через PCA головних осей;
* коефіцієнт округлості $C = \frac{4\pi S}{P^2}$ (за ручним периметром контуру);
* кількість шпильок $K_{\text{studs}}$ та текстурні ознаки поверхні (`LBP`/`GLCM`, якщо передані в `metadata` для розрізнення `brick` / `tile`).

### Крок 2: Визначення кольору (`src/lego_cv/core/color_classifier.py`)
Спільний Модуль Б приймає початкове `RGB`-зображення, інстанс-маску та список `BrickDetection`:
1. Застосовує ручну бінарну ерозію $3\times 3$ (`binary_erode_manual`), щоб відсікти крайову тінь.
2. Переводить пікселі у `HSV` (`rgb_to_hsv_manual`), відсіює тіні заглиблень ($V < 40$) та відблиски ($S < 25 \land V > 235$) і визначає колір за **медіаною `(H, S, V)`** (із циклічною обробкою червоного сектору `H`) за палітрою з `configs/default.json`.
3. Якщо вхідне зображення фактично чорно-біле (`R == G == B`, як на рендерах Kaggle), модуль повертає `"Grayscale"` (або `"Unknown"`), не перериваючи роботу Кроку 1.

**Правило для агентів:** Ніколи не дублюйте обчислення геометрії або визначення кольору всередині файлів `p1..p4`. Будь-які зміни спільних класифікаторів вносяться виключно у `src/lego_cv/core/`.

## 4. Конфігурація, відтворюваність та крайні випадки (Критерій C2)

* **Жодного хардкоду параметрів:** усі пороги, розміри ядер, коефіцієнти та діапазони HSV мають читатися з `configs/*.json` і підтримувати перевизначення через CLI `--param section.key=value`.
* **Детермінованість:** будь-яка генерація шуму або стохастична операція використовує `np.random.default_rng(config["seed"])`.
* **Захист від крайніх випадків (C2):**
  * порожні (0 байт), відсутні, пошкоджені або непідтримувані файли викликають `ImageLoadError` і не зупиняють пакетний прогін `runner.py`;
  * 1-канальні (grayscale) та 4-канальні (RGBA) зображення коректно нормалізуються у 3-канальний `RGB uint8`;
  * захищайте формули від ділення на нуль (`MSE == 0 -> PSNR = inf`, `SSIM` із константами $C_1, C_2$, нульовий периметр або однорідний кадр без аварійних винятків).

## 5. Обов'язкові ворота якості та політика ШІ (C3, C4, A1, M)

1. **Автотести на малих матрицях (C3):** кожна реалізована стадія, класифікатор або метрика повинні мати щонайменше один короткий тест на матриці $3\times 3$, $5\times 5$ чи $8\times 8$ із заздалегідь обчисленим вручну очікуваним результатом.
2. **Документування коду (A1):** усі публічні функції та класи мають Google-style docstrings, а нетривіальні алгоритмічні кроки — лаконічні коментарі.
3. **Обов'язкова перевірка перед завершенням будь-якого завдання:**
   ```bash
   pylint src tests scripts   # ціль: 10.00/10, 0 зауважень (критерій C4)
   pytest -v                  # 100% проходження тестів (критерій C3)
   lego-cv --list-pipelines   # перевірка CLI (критерій E1)
   ```
4. **Декларування ШІ (`META-USAGE.md`, множник `M`):** будь-яке застосування AI-агента для генерації коду, тестів чи документації має бути зафіксовано новим записом у `META-USAGE.md`. Автор коду зобов'язаний розуміти кожен рядок у своїй зоні для персонального захисту (критерій **E1**).
